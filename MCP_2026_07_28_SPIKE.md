# MCP 2026-07-28 Stateless Migration — Spike

**Date:** 2026-06-06 · **Spec freeze:** 2026-07-28 (7.4 weeks) · **Gateway cutover target:** 2026-07-14 (5.4 weeks)

## Verdict

The migration is **smaller than feared** because the gateway is a thin wrapper and
`meok_x402.py` was designed stateless (payment travels per-request in
`_meta["x402/payment"]` — zero session coupling, verified by grep). The plan is
three phases; **Phase 0 ships in this PR** and de-risks the infrastructure today.

## What the 2026-07-28 RC changes (verified 2026-06-06 against the official blog)

1. `initialize`/`initialized` handshake **removed** — client info/capabilities move
   to `_meta` on every request
2. `Mcp-Session-Id` header **removed** — no sticky sessions; plain round-robin LBs work
3. New required headers: `Mcp-Method`, `Mcp-Name` (+ `MCP-Protocol-Version: 2026-07-28`);
   servers must reject header/body mismatches
4. Error `-32002` → standard `-32602` (Invalid Params)
5. `ttlMs`/`cacheScope` caching metadata on `tools/list` & `resources/read`
6. W3C Trace Context (`traceparent`/`tracestate`/`baggage`) formally specified

## SDK support matrix (checked 2026-06-06)

| SDK | Version | 2026-07-28 support |
|---|---|---|
| `mcp` (our exact pin) | 1.27.2 (latest, 2026-05-29) | ❌ not yet — Tier-1 SDKs expected within the RC window (by 07-28) |
| `fastmcp` standalone | 3.4.2 **stable** (3.4.0 GA'd this week) | ✅ RC support since 3.4.0b1 |

We cannot switch the gateway to standalone `fastmcp` 3.x unilaterally: flagships
construct their `mcp` objects with the SDK-bundled `mcp.server.fastmcp.FastMCP`,
and `http_server.py` wraps `server.mcp` — the object type is flagship-owned.
A gateway-only switch would need a shim; that's the contingency, not the plan.

## Plan

- **Phase 0 — now (this PR):** flip stateless mode in `http_server.py`. e2e-verified
  locally against eu-ai-act-compliance-mcp==1.8.1 (see PR). No client-visible
  breakage: old-spec clients still initialize; the SDK handles it per-request.
- **Phase 1 — the week the SDK ships (watch weekly, expected before 07-28):**
  bump `mcp==` pin in requirements-gateway.txt + constraints.txt; update
  `tests/e2e_smoke.py` to the new client; verify x402 challenge/payment `_meta`
  round-trip under the new protocol version; CI green = done.
- **Phase 2 — cutover by 2026-07-14:** rebuild + re-push 8 GHCR images;
  fleet-sync the `mcp<2` upper bound + FLEET_BASE.md checklist; bump the
  flagship gold-standard e2e pin deliberately.
- **Contingency (trigger: no SDK release with RC support by 2026-07-01):**
  prototype the gateway on `fastmcp` 3.4.x behind a `server.mcp`-to-3.x shim,
  or pin AgentCore/Cloud Run deployments to the 2025-11-25 protocol version
  (clients negotiate down) and slip cutover — decision point for Nick.
